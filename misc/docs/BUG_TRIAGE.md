## Deploy model

Process: **creating a git tag = deployed.** To decide if a fix is live:

- Find the fix commit: `git log --oneline -i --grep='#<reportid>'` (commit messages reference `BGA #<id>`).
- Is it in the latest tag: `git merge-base --is-ancestor <commit> <latest-tag> && echo LIVE`.
- List tags containing it: `git tag --contains <commit> --sort=creatordate | head`.

In the latest deployed tag -> **Fixed**. Committed/tagged but that tag not deployed -> **Waiting for deploy**.

To confirm what is actually live (and avoid guessing whether a tag is deployed), open the studio manage-game page: https://studio.boardgamearena.com/studiogame?game=wayfarers - the "Online version" field shows the current production version string, and the "Versions available for production" list marks one entry "(Current PRODUCTION version)" with its release-note summary. Match a report's fix to that release note to confirm it shipped. (This is the authoritative deploy check; the git-tag steps above are the local proxy.)

## Investigation and tests

- Tests live under `phptests/` (flat, mirroring op/source names, e.g. `Op_rerollTest.php`).
- A reproducing test must be **green**, asserting the current buggy behavior, with a comment pinning it for `BGA #<id>` (flip the assertion when the fix lands) - see the skill's CONFIRMED note.

- [ ] BGA #231680 (display, mobile) - CONFIRMED 2026-08-22, root cause measured. The first Land/Water card in the panorama sits 3.39px lower than every following card, so the row breaks at the board/first-card junction only; cards 2..4 align with each other exactly. Cause: Game.ts:722 special-cases `x == 1` and parents the first card straight into `pboard_{color}` instead of a `pboard_column_1_{color}` wrapper like its siblings. Land/water cards are anchored `bottom: 8.5%` of their own container (Cards.scss:144), and the two containers are not the same height - `.pboard` takes `aspect-ratio: 798/1024` (Boards.scss:155), which at width 376.95px renders 483.70px, while `.column` uses the fixed `$pboardHeight: calc($cardHeight * 2.4)` = 480px (\_variables.scss:67). The 3.70px height gap times (1 - 0.085) = 3.39px, exactly the measured offset. MEASURED in the real client, not inferred: harness snapshot with 4 water cards forced into `tableau_6cd0f6`, geometry read via headless Chrome - card 1 top 341.59, cards 2/3/4 top 338.20, board's own pre-printed `card_home_*` row top 344.02 (a third baseline, `.card_home { bottom: 8% }`). No repo test: jsdom does no layout, so `npm run jstests` cannot assert this - reproduce with `npm run play` plus a DOM measurement. Two fix directions, maintainer's call: give the first card its own `pboard_column_1_*` wrapper so all cards share one containing block (but `.pboard .card[data-state="1"] { right: 0% }` may be a deliberate tuck against the board edge), or derive `$pboardHeight` from the same 798/1024 ratio so the two containers agree.
- [ ] AUTO ERROR (no report) - FIXED in code 2026-08-24 (`:scope > *`, Game.ts:666), awaiting deploy; no other `&` selector remains in src/. `& > *` is not a valid `querySelectorAll` selector. Game.ts:666, inside `onLeavingState`: `$("selection_area").querySelectorAll("& > *")`. `&` only works in `querySelector` on engines with CSS-nesting relative-selector support, so older engines throw a SyntaxError, `onLeavingState` aborts, and the `selection_area` children are never removed (unhandled promise rejection). ONE defect spread over 6 studio issue ids because the grouping keys off the stack and the wording differs per engine - Firefox/Gecko says "Element.querySelectorAll: '& > \*' is not a valid selector" (ids A48Z 5 events, 9RJA, 9M29, 9FQB), WebKit says "The string did not match the expected pattern" with `DOMException.code 12` (ids 9YMK, 9EMS). Combined blast radius ~10 events / ~7 users, still unfixed as of the 260823-2009 deploy - the call site is unchanged at Game.ts:666 (last seen 2026-08-21, i.e. on the previous release). NOT just an old-Firefox case, which is why it is worth fixing despite the browser-compat stance: culprits seen are Firefox 115 (Win7/8.1), **Safari 16.3 on macOS**, and **Mobile Safari 16.1 on iPhone**. Fix is `:scope > *`, which is the standard spelling and universally supported - no compat compromise.
